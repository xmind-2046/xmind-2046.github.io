纯 IPv6 VPS 搭建 Hysteria 2 节点：从零到稳定运行的完整教程

面向 纯 IPv6（IPv6-Only）VPS 的 Hysteria 2 搭建全流程：先装 Cloudflare WARP 打通 IPv4 出口，再安装 Hysteria 2、生成带 SAN 的自签证书、客户端固定证书零警告接入。
适用环境：Ubuntu 24.04 · 64bit，EUserv 等免费纯 IPv6 VPS 同样适用。文中所有命令均经真实部署验证。

前置条件速查（任何一项不满足，后面都会以各种奇怪现象报错）：

  • ✅ 服务器：Ubuntu 24.04，有公网 IPv6，可用 root 或 sudo
  • ✅ 域名：一个 AAAA 记录指向 VPS IPv6 的域名（不要用 IP 直连，Hysteria 2 依赖 SNI）；若托管在 Cloudflare 务必开 DNS Only（灰云），橙云代理模式不支持 UDP

阅读与执行方式

  1. 命令默认以 root 执行；如果使用普通用户，请在需要时加 sudo，并确认该用户属于 sudo 组。

① 首先安装 Cloudflare WARP（打通 IPv4 出口）

纯 IPv6 VPS 只有 IPv6 出口：访问 IPv4 网站（GitHub、多数 CDN）会报 network is unreachable。而 Hysteria 2 代理出站的目标大多是 IPv4 网站，所以第一步先装 WARP，借 Cloudflare 的隧道获得 IPv4 出口，后续下载、更新、代理全都能跑通。

WARP 常见边界

WARP 只负责 VPS 的出站访问，不会替代 Hysteria 2 的监听端口，也不会让纯 IPv6 VPS 获得一个可被客户端直连的公网 IPv4。客户端仍然需要通过 AAAA 记录访问 VPS。若服务商已经提供原生 IPv4，不必为了“看起来完整”强行安装 WARP，但仍可按需保留它作为出站策略。

⑤ 证书（生成带 SAN 的自签证书）

5.1 为什么必须带 SAN

🔴 最大的坑：Go 1.15+（sing-box / Xray 均为 Go 编写）校验 TLS 只认 subjectAltName（SAN），不认 CN。
只写 -subj "/CN=域名" 的证书即使被客户端信任，也会被直接拒绝连接。

5.2 生成证书

DNS 与 IP 必须写在同一条 -addext 里（逗号分隔）——写成两条会报 Duplicate extension 导致生成失败：

需要修改：-subj 中的域名，以及 subjectAltName 中的 DNS 和 IPv6。DNS 必须与客户端 SNI、连接域名一致。

验证 SAN 已写入（必须能看到 DNS:yourname.ddns.org, IP:2001:db8:abcd::1）：

5.3 修正文件权限（关键，最容易漏）

🔴 官方脚本创建的服务以 hysteria 用户运行（非 root）。openssl 生成的文件属主是 root，服务会报 permission denied 起不来。

5.4 防火墙放行 + 启动

预期看到 active (running)，日志含 server up and running {"listen": ":8443"}。

若启动失败，用 journalctl -u hysteria-server -n 30 --no-pager 看报错，常见两类：

  • tls.key: permission denied → 回到 5.3 修正属主
  • tls.cert: no such file or directory → 证书没生成成功（检查 5.2 的 openssl 是否报错）

5.5 从外部确认 UDP 端口

服务器本地 ss 只能证明进程正在监听，不能证明云平台安全组或上游防火墙已经放行。请同时检查：

如果 VPS 服务商有独立的安全组/网络 ACL，还要在控制台新增 UDP 8443 入站规则。TCP 8443 对 Hysteria 2 本身不是必需的；不需要时可以关闭，以减少暴露面。

6.2 手动配置（推荐：固定证书方案，零警告）

原理：自签证书可以做到”既不用跳过验证、又没警告”——把服务器证书固定到客户端。

推荐顺序：先用 insecure=1 验证网络和密码，再切换为固定证书并关闭“跳过证书验证”。这样能把网络故障与证书信任故障分开定位。

先在服务器上查看证书，复制完整多行文本（-----BEGIN CERTIFICATE----- 到 -----END CERTIFICATE-----）：

然后 v2rayN 节点编辑（sing-box 核心）：

字段 填写 备注
协议类型 Hysteria 2 —
核心 sing_box ⚠️ 别用 Xray 跑这个节点
服务器地址 yourname.ddns.org 或 [2001:db8:abcd::1]
端口 8443 与服务端一致
认证密码 YourStrongPassword!2026 与服务端一致
SNI yourname.ddns.org 必须与证书 SAN 一致
跳过证书验证 不勾选 固定证书后可以放心关闭
固定证书 粘贴完整 PEM 多行文本 不是公钥哈希（填哈希会报错）

🔴 固定证书的坑：

  • 填的是证书文本（PEM），不是 openssl 算出来的公钥哈希。把哈希填进 Xray 核心会直接启动失败：encoding/hex: invalid byte: 'U'。
  • 证书与密钥是一对，服务器换过证书后，客户端必须同步换，否则连不上（见第 ⑦ 节）。

完成客户端配置后，按以下顺序验证：

  1. 先确认节点地址解析到当前 VPS：nslookup -type=AAAA yourname.ddns.org。
  2. 在客户端仅开启该节点，访问一个 IPv4-only 站点和一个 IPv6 站点。
  3. 确认服务端日志没有持续的 authentication failed、tls 或 network is unreachable。
  4. 固定证书模式稳定运行后，删除临时的 insecure=1 链接，避免误用不安全配置。

6.3 核心选择

核心 结论
sing-box ✅ 推荐。固定证书（PEM）与 insecure 均正常
Xray ❌ 实测 Hysteria2 的证书相关字段映射有 bug（hex 解析错误 / 无法信任自签证书）

⑦ 注意事项 & 更新配置说明

7.1 常见故障速查

现象 原因 解决
测延迟总是 -1 本机 IPv6 不通 / 域名解析错误 / 橙云代理 依次排查：本机 ping -6、nslookup -type=AAAA、Cloudflare 改灰云
能连上但网页打不开，日志报 dial tcp4: network is unreachable VPS 缺 IPv4 出口 重跑 bash menu.sh 4，验证 curl -4 ... | grep warp= 为 on
客户端提示 AllowInsecure / 报 x509: certificate signed by unknown authority 未固定证书，或证书 SAN 缺域名 按 6.2 固定证书；检查 SAN
服务启动失败 permission denied（tls.key） 证书属主不是 hysteria chown hysteria:hysteria + chmod 600/644 + 重启
客户端启动失败 encoding/hex: invalid byte 固定证书填成了哈希 清空改粘完整 PEM 文本
本机 IPv6 突然不通 / DNS 异常 本机开着 Cloudflare WARP 或其它 VPN 使用 v2rayN 期间建议断开本机 WARP；交叉验证 nslookup 域名 223.5.5.5
服务器全部端口不通（掉线） 服务器端问题 / IP 变更 / 免费机被回收 登录服务商控制台查实例状态与当前 IP，必要时重启

7.3 更新配置时的同步规则

任何服务端变更，记得客户端要同步改：

服务端改动 操作 客户端需同步
换证书 重新生成 cert/key → chown/chmod → 重启服务 固定证书必须换新 PEM，否则 unknown authority
改密码 改 config.yaml 的 auth.password → 重启 更新认证密码
改端口 改 listen: + ufw allow 新端口 → 重启 更新端口

7.4 推荐加固：SSH 换端口（Ubuntu 24.04 必看）

⚠️ Ubuntu 24.04 的坑：默认启用 ssh.socket（套接字激活），监听端口由 systemd 持有——sshd_config 里的 Port 会被它无视。改完端口连不上时，先查 systemctl status ssh 是否显示 TriggeredBy: ● ssh.socket。

7.5 免费 VPS 日常维护

事项 说明
保活 EUserv 等免费实例定期登录控制台（建议每 3~4 周），防止被回收
IP 变更 掉线先查控制台当前 IP；变更后同步更新 DDNS 与客户端节点
证书有效期 本方案证书 10 年（-days 3650），到期前重新生成并同步客户端
密码强度 auth.password 用高强度随机密码，勿用教程示例值
负载虚高 容器内 CPU 100% idle 但 loadavg 3+ 是 LXD 宿主负载，超售常态，忽略即可，不影响性能
